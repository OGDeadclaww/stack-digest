### 2025-12-02 — Sloth Bytes
- **Lesson:** "Write the dumbest version first" workflow: crude proof-of-concept with no abstractions → deliberately try to break it → identify real requirements from what actually broke → only then refactor with intention. Premature architecture before you understand the problem usually costs more than it saves.
- **Lesson:** Folding AI into that workflow: ask it to write the dumb first version fast, separately ask "what edge cases should I test for X," and only after real requirements are known ask it to refactor toward those specific discovered constraints — not a "production-ready" version upfront.
- **Lesson:** Concrete signals code needs refactoring now: the same logic copy-pasted 5+ times, bugs recurring in the same area, onboarding to one part taking unreasonably long, or a once-hour change now taking a full day because it touches scattered places.
